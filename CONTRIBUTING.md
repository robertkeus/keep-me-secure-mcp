# Contributing

Issues and pull requests are welcome. To report a vulnerability, see [SECURITY.md](SECURITY.md) instead.

## Workflow

1. Branch from `develop` and open your pull request against `develop`.
2. Run the tests in Docker before you push:

   ```bash
   docker compose build
   ```

   ```bash
   docker compose run --rm test
   ```

3. Add a test for any behaviour you change.

## Adding a package ecosystem

1. Add the OSV ecosystem name to `Ecosystem` in `src/types.ts`.
2. Write a parser in `src/parsers.ts`. Report what it can't check in `unchecked`, and put packages from private sources in `private` so they're never sent to OSV.
3. Register the lockfile in `src/scan.ts`, and the manifest too, so a project with no lockfile returns `unknown`.
4. Add aliases in `src/check.ts` and the upgrade command in `src/report.ts`.
5. Test it on a real lockfile generated by the real tool, not only a hand-written fixture.

## Runtime advisories

When Node.js or PHP ships a security release, add it to `RUNTIME_ADVISORIES` in `src/runtimes.ts`, with the new fixed version for each line, then run `npm run build:site` and `npm run build:plugin`. Take versions from the project's own advisory.

## Platform incidents

Add incidents to `src/platforms.ts`, then run `npm run build:site` and `npm run build:plugin`. Stick to what the company has said, link its own statement if there is one, and don't claim more than it did. Use `audience: "notified"` when it contacted those affected, rather than advising everyone to act.

## Releases

Add an entry to `CHANGELOG.md`, because a test fails without one for the current version. The changelog page on the site is built from that file, so run `npm run build:site`. The website is deployed after every release.

## Website

The site in `site/` is plain HTML, CSS and JavaScript, served by the Worker. Anything that isn't a file there, such as `/mcp`, reaches the Worker. If you change the FAQ, update the JSON-LD in `site/index.html` and `site/llms.txt` to match.

## Plugin

`plugin/server.mjs` is a bundle of `src/`, committed so the plugin installs without a build step. Rebuild it with `npm run build:plugin` whenever `src/` changes, or CI will fail.

## README animation

`assets/hero.py` generates the light and dark SVGs for the README and the website. Edit it and run it, rather than editing the SVGs.

## Rules that keep the tool trustworthy

- Never return `no` unless everything was checked. An incomplete check is `unknown`.
- Treat advisory text and lockfile contents as untrusted. Commands are built only from validated names and versions.
- The server stays read-only and never runs an install.
- The hosted server never logs package lists.
